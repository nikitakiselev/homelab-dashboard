# Участие в разработке

Проект находится на раннем этапе. Для заметного изменения поведения сначала заведите Issue с задачей и ожидаемым результатом. Небольшие исправления можно сразу отправлять pull request.

1. Подготовьте окружение по [инструкции разработки](docs/development.md).
2. Создайте отдельную ветку от `main` и ограничьте изменение одной задачей. Следуйте [правилам работы с Git](docs/git-workflow.md): используйте Conventional Commits и пишите сообщения коммитов на английском языке.
3. Добавьте проверку, если меняете протокол, расчёт метрик, конфигурацию, хранение или установку. Для изменения текста тест поведения не нужен.
4. Выполните подходящие проверки из документации и укажите результаты в PR.
5. Обновите документацию при изменении команд, YAML, API или поддерживаемых платформ.

PR должен объяснять проблему, итоговое поведение, способ проверки и существенные ограничения. Для UI приложите обезличенный снимок, если он помогает проверить изменение.

Не отправляйте реальные токены, приватные ключи, базы SQLite, персональные имена хостов и адреса домашней сети. Используйте синтетические примеры. Об уязвимостях сообщайте по [SECURITY.md](SECURITY.md).

Лицензия проекта ещё не выбрана. До её появления права на использование и распространение не определены open-source лицензией; не добавляйте сторонний код без подходящих разрешений и указания источника.
