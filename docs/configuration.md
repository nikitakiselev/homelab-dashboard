# Конфигурация агента и дашборда

Настройки Linux-агента: `/etc/homelab/agent.yaml`. Установщик агента создаёт файл только при первом запуске и сохраняет при обновлении. Дашборд не читает YAML агента и не имеет встроенного сборщика.

```yaml
server:
  bind: 0.0.0.0
  port: 9108
collection:
  interval_seconds: 5
  disks:
    enabled: true
    interval_seconds: 60
  gpu:
    enabled: true
    interval_seconds: 5
network:
  interfaces: []
history:
  retention_days: 90
  path: /var/lib/homelab-agent/agent.sqlite
```

| Параметр | Значение |
|---|---|
| `collection.interval_seconds` | CPU, память и сеть: от 1 до 300 секунд, по умолчанию 5 |
| `collection.disks` | Включение дисков/SMART и период опроса, по умолчанию 60 секунд |
| `collection.gpu` | Включение GPU и период опроса, по умолчанию 5 секунд |
| `network.interfaces` | Список интерфейсов; пустой список включает автоматический выбор |
| `history.retention_days` | От 1 до 3650 дней; по умолчанию 90 |
| `history.path` | SQLite отдельного агента; относительный путь считается от каталога YAML |
| `server.bind`, `server.port` | Адрес и порт отдельного агента (порт 1–65535; по умолчанию 9108) |

Дашборд независимо хранит центральную копию истории: по умолчанию 90 дней, настройка `python3 -m homelab.server --retention-days 90` (от 1 до 3650 дней). Срок хранения агента не меняет срок хранения дашборда. UI показывает периоды сутки, 7, 30 и 90 дней; при более коротком сроке отображаются сохранившиеся данные. Старый `/etc/homelab/collector.yaml` больше не применяется и автоматически не удаляется.

Интервалы дисков и GPU допускают значения от 1 до 86400 секунд. Linux-сборщик вообще не отправляет ATA/SATA SMART-команды и проверки питания. Для HDD используется пассивный режим; при наличии HDD на хосте автоматические запросы заполнения файловых систем также отключены, включая общие тома SSD/HDD. Увеличение интервала SMART не заменяет эту защиту. Подробности и ограничения — в [описании метрик](metrics.md#накопители). История агрегируется по 5 минутам независимо от частоты сбора. Таймаут доступности агента учитывает объявленный интервал сбора, чтобы редкий сбор не считался отключением.

## Проверка и применение

```sh
sudo homelab-agent check-config --config /etc/homelab/agent.yaml
sudo homelab-agent restart
```

Изменение YAML агента требует перезапуска только `homelab-agent`; дашборд продолжает работать. Горячей перезагрузки YAML пока нет. Ошибочные, неизвестные и повторяющиеся ключи отклоняются до запуска. Токен в YAML не принимается.

По умолчанию systemd разрешает запись в каталог состояния службы. Если меняете путь SQLite за пределы `/var/lib/homelab-agent`, повторите установку агента: установщик создаст каталог и обновит `ReadWritePaths` службы.

## Приоритеты

1. `--bind`, `--port`, `--data` отдельного агента перекрывают соответствующие значения YAML.
2. `HOMELAB_INTERFACES`, если задан, перекрывает `network.interfaces` для совместимости с прежней настройкой.
3. YAML перекрывает встроенные значения по умолчанию.

`HOMELAB_AGENT_TOKEN` и `HOMELAB_DASHBOARD_TOKEN` хранятся в env-файлах с правами 0600.

Для локального запуска:

```sh
sudo homelab-agent run --config ./my-agent.yaml
python3 -m homelab.server --data ./data/dashboard.sqlite --retention-days 90
```

Без YAML агент использует значения по умолчанию. Парсер YAML встроен в Go-бинарник; дашборду нужен только стандартный Python без PyYAML.

При смене порта перезапустите агент и укажите новый порт при добавлении хоста в дашборд. Если порт занят, запуск завершится с ошибкой; другой порт автоматически не выбирается.

Дисковая активность Linux (`/proc/diskstats`) собирается с интервалом `collection.interval_seconds` и отключается через `collection.disks.enabled: false`. `collection.disks.interval_seconds` управляет медленным опросом сведений о дисках и SMART. Подробнее: [чтение и запись дисков](metrics.md#чтение-и-запись-дисков).
