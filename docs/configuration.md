# Конфигурация агента и дашборда

Настройки Linux-агента: `/etc/homelab/agent.yaml`. Установщик агента создаёт файл только при первом запуске и сохраняет при обновлении. Дашборд не читает YAML агента и не имеет встроенного сборщика.

```yaml
server:
  bind: 0.0.0.0
  port: 9108
collection:
  interval_seconds: 5
  disks:
    enabled: true
    interval_seconds: 60
  gpu:
    enabled: true
    interval_seconds: 5
network:
  interfaces: []
history:
  retention_days: 90
  path: /var/lib/homelab-agent/agent.sqlite
```

| Параметр                      | Значение                                                                                                                          |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `collection.interval_seconds` | CPU, память и сеть: от 1 до 300 секунд, по умолчанию 5                                                                            |
| `collection.disks`            | Включение дисков, период метаданных/NVMe SMART, по умолчанию 60 секунд                                                            |
| `collection.smart`            | Редкий ATA SMART: `enabled: false`, `interval_seconds: 86400`, `serials: []`; включение требует непустого списка серийных номеров |
| `collection.gpu`              | Включение GPU и период опроса, по умолчанию 5 секунд                                                                              |
| `network.interfaces`          | Список интерфейсов; пустой список включает автоматический выбор                                                                   |
| `history.retention_days`      | От 1 до 3650 дней; по умолчанию 90                                                                                                |
| `history.path`                | SQLite отдельного агента; относительный путь считается от каталога YAML                                                           |
| `server.bind`, `server.port`  | Адрес и порт отдельного агента (порт 1–65535; по умолчанию 9108)                                                                  |

Дашборд независимо хранит центральную копию истории: по умолчанию 90 дней, настройка `python3 -m homelab.server --retention-days 90` (от 1 до 3650 дней). Срок хранения агента не меняет срок хранения дашборда. UI показывает периоды сутки, 7, 30 и 90 дней; при более коротком сроке отображаются сохранившиеся данные. Старый `/etc/homelab/collector.yaml` больше не применяется и автоматически не удаляется.

Интервалы дисков и GPU допускают значения от 1 до 86400 секунд. По умолчанию ATA SMART отключён. Явный режим `collection.smart` разрешает опрос выбранных прямых SATA/ATA-дисков не чаще раза в сутки, только после наблюдаемой дисковой активности и проверки питания. Неизвестное состояние, USB/SAS и отсутствие серийного номера запрещают запрос. Ошибки и пропуски также расходуют суточный бюджет, который хранится в SQLite. При наличии HDD или неизвестного типа на хосте запросы заполнения файловых систем отключены для всех дисков. Подробности и ограничения — в [описании метрик](metrics.md#накопители). История агрегируется по 5 минутам независимо от частоты сбора. Таймаут доступности агента учитывает объявленный интервал сбора, чтобы редкий сбор не считался отключением.

## Проверка и применение

```sh
sudo homelab-agent check-config --config /etc/homelab/agent.yaml
sudo homelab-agent restart
```

Изменение YAML агента требует перезапуска только `homelab-agent`; дашборд продолжает работать. Горячей перезагрузки YAML пока нет. Ошибочные, неизвестные и повторяющиеся ключи отклоняются до запуска. Токен в YAML не принимается.

По умолчанию systemd разрешает запись в каталог состояния службы. Если меняете путь SQLite за пределы `/var/lib/homelab-agent`, повторите установку агента: установщик создаст каталог и обновит `ReadWritePaths` службы.

## Приоритеты

1. `--bind`, `--port`, `--data` отдельного агента перекрывают соответствующие значения YAML.
2. `HOMELAB_INTERFACES`, если задан, перекрывает `network.interfaces` для совместимости с прежней настройкой.
3. YAML перекрывает встроенные значения по умолчанию.

`HOMELAB_AGENT_TOKEN` и `HOMELAB_DASHBOARD_TOKEN` хранятся в env-файлах с правами 0600.

Для локального запуска:

```sh
sudo homelab-agent run --config ./my-agent.yaml
python3 -m homelab.server --data ./data/dashboard.sqlite --retention-days 90
```

Без YAML агент использует значения по умолчанию. Парсер YAML встроен в Go-бинарник; дашборду нужен только стандартный Python без PyYAML.

При смене порта перезапустите агент и укажите новый порт при добавлении хоста в дашборд. Если порт занят, запуск завершится с ошибкой; другой порт автоматически не выбирается.

Дисковая активность Linux (`/proc/diskstats`) собирается с интервалом `collection.interval_seconds` и отключается через `collection.disks.enabled: false`. `collection.disks.interval_seconds` управляет медленным опросом сведений о дисках и SMART. Подробнее: [чтение и запись дисков](metrics.md#чтение-и-запись-дисков).

### Постепенное включение ATA SMART

Установщик теперь включает пакет `hdparm`. Если агент обновлялся только командой `homelab-agent upgrade`, существующий набор системных пакетов не меняется: проверьте `homelab-agent doctor` и при отсутствии утилиты установите `sudo apt-get install hdparm`. Отсутствие утилиты запрещает SMART-запрос, а попытка всё равно расходует суточный бюджет.

Сначала убедитесь, что `history.path` находится на SSD и другие службы не дублируют опрос. Серийный номер возьмите из аппаратного списка агента или `lsblk -o NAME,MODEL,SERIAL,TRAN,ROTA`. Для первого испытания укажите **один** прямой SATA-диск:

```yaml
collection:
  smart:
    enabled: true
    interval_seconds: 86400
    serials: [EXAMPLE-HDD-001]
```

Добавьте блок к существующему `collection`, не заменяя остальные настройки. Проверьте конфигурацию командой `homelab-agent check-config`, затем перезапустите `systemctl restart homelab-agent`. Диск не будет опрошен сразу только из-за рестарта: агент дождётся обычной активности и доступного бюджета. Для остановки опроса установите `enabled: false` и перезапустите службу; кэш останется доступен. Интервал SMART допускает 86400–7776000 секунд, дубли и пустые серийные номера запрещены. В этом режиме основной `collection.interval_seconds` должен быть не больше 30 секунд, чтобы активность наблюдалась на коротких интервалах.

Проверка на оборудовании: сохраните исходный снимок во время обычного использования, затем наблюдайте минимум полный настроенный цикл сна и следующий день. Сравнивайте время/число попыток, способность диска засыпать и прирост `Load_Cycle_Count`/`Start_Stop_Count` с обычной нагрузкой без мониторинга. Не запускайте частый `smartctl` ради проверки: он сам изменяет наблюдаемое поведение. Рост счётчиков не позволяет без контроля нагрузки однозначно приписать циклы агенту. При аномалиях отключите режим для этого диска. Моки не подтверждают физическую безопасность.

## Доступ к дашборду из домашней сети

`HOMELAB_DASHBOARD_TRUSTED_NETWORKS` задаёт через запятую IP/CIDR клиентов с полным доступом без токена. По умолчанию список пуст. Например, `192.168.50.0/24` разрешает всю указанную домашнюю подсеть; для остальных клиентов остаётся `HOMELAB_DASHBOARD_TOKEN`. Адрес определяется по TCP-соединению, без доверия к заголовкам прокси. [Настройка Docker и ограничения прокси](docker.md#вход-без-токена-в-домашней-сети).

В установке systemd добавьте переменную в `/etc/homelab/dashboard.env` и выполните `sudo systemctl restart homelab-dashboard`. При прямом запуске Python переменная должна быть экспортирована в окружение процесса: файл `.env` автоматически читает Docker Compose, сам Python-сервер его не загружает.
