# Домашняя страница с приложениями

Дата: 2026-10-26. Статус: согласован пользователем; разрешена автономная реализация.

## Назначение

Домашняя страница должна позволять быстро открыть веб-интерфейс любого нужного
сервиса homelab, не запоминая адреса и порты. Мониторинг остаётся частью этого же
приложения. Пользователь предложил сетку иконок в духе macOS Launchpad, автоматический
подбор оформления для известных приложений, нейтральную blueprint-иконку для
остальных и отметку приложений, доступных извне.

Пользователь также предложил первоначально собрать приложения непосредственно
через доступ к его серверам. Разовый сбор выполнен: проверены три узла Proxmox,
метаданные их гостей, Docker, маршруты Caddy и ссылки существующей Homepage.
Подготовлен частный каталог из 33 ярлыков, для 16 найдены внешние адреса. Это
сведения о конфигурации, а не подтверждение исправности приложений или доступа
из интернета. Ссылки на отдельный AI-хост и роутер взяты из Homepage; сами эти
хосты не обследованы. Реальные адреса и каталог не входят в репозиторий.

## Рассмотренные подходы

1. Ручное добавление каждой ссылки. Простая реализация и подходит для любых
   сервисов, но требует много действий при первоначальном заполнении.
2. Постоянное обнаружение и автоматическое добавление. Уменьшает ручную работу,
   но требует источника метаданных, правил отбора, обработки дублей и неоднозначных
   адресов. Сам факт существования контейнера не означает наличие пользовательского
   веб-интерфейса.
3. Постоянное обнаружение с подтверждением предложений. Устраняет часть лишних
   ярлыков, но сохраняет сложность обнаружения и отдельный список предложений.
4. Разовый сбор помощником с последующим редактированием каталога в UI.
   Пользователь предложил этот путь в обсуждении. Он позволяет начать с уже
   заполненной страницы. Новые приложения в первой версии добавляются ссылкой;
   помощник может повторить сбор по запросу. Автоматического обновления состава нет.

Для первой версии предлагается подход 4. Это предложение о границах реализации,
а не уже согласованное решение отказаться от обнаружения навсегда.

## Главная страница

Следующие подробности — предлагаемые решения помощника, доступные для изменения
при согласовании документа.

- `/` становится «Главной». Текущий «Обзор» переносится на `/overview`.
  `/servers`, страницы серверов и `/storage` сохраняют свои адреса.
- Навигация: «Главная», «Обзор», «Серверы», «Накопители». Используется существующее
  светлое оформление, шрифты, синие акценты и мобильная навигация.
- Основное содержимое — сетка приложений с крупной иконкой и названием. Адрес,
  сервер и технические метаданные доступны в деталях, не занимая каждую плитку.
- Сверху располагаются поиск и «Добавить приложение». Поиск фильтрует названия
  и группы. Enter открывает результат только при явном выборе элемента.
- Приложения объединяются в именованные группы. Первая версия показывает группы
  секциями на одной странице; поиск работает сразу по всем группам. Пагинации нет.
- Количество колонок зависит от ширины экрана. Полный список из примерно 30
  приложений должен оставаться удобным на ноутбуке и телефоне.
- Перед сеткой — компактный виджет состояния подключённых серверов с переходом
  к мониторингу. Данные берутся из существующих метрик. Если они недоступны,
  виджет сообщает об этом; каталог остаётся работоспособным.
- Дополнительные виджеты приложений, погода, часы и конструктор виджетов в первую
  версию не входят. Их состав пока не выбран пользователем.

Под запуском понимается открытие ссылки в новой вкладке. Главная не управляет
запуском, остановкой или установкой контейнеров.

## Внутренние и внешние адреса

У приложения есть выбранный адрес открытия, необязательный локальный адрес и
необязательный внешний адрес. Любой из двух адресов можно выбрать основным.
Переключать его автоматически по предполагаемому местоположению браузера не нужно.
При наличии второго адреса он доступен в меню приложения.

Для внешнего доступа различаются три состояния:

- `confirmed`: владелец явно подтвердил доступ извне при редактировании приложения.
  Рядом с иконкой показывается маленький глобус с подсказкой «Доступно извне» и
  внешним адресом. Подтверждение означает настройку владельца, а не непрерывную
  проверку доступности.
- `unverified`: внешний адрес найден в конфигурации, но не подтверждён. Показывается
  приглушённый глобус с подсказкой «Внешний адрес найден · доступ извне не проверен».
- `unknown`: внешнего адреса нет в каталоге; глобус отсутствует. Это не утверждение,
  что сервис невозможно открыть извне.

При первичном импорте найденные внешние адреса получают только `unverified`.
Маршрут Caddy, имя домена и работающий контейнер не переводят их в `confirmed`.
Изменение внешнего адреса сбрасывает подтверждение. Поле `confirmed` нельзя
сохранить без внешнего HTTP(S)-адреса. Иконка имеет доступное текстовое описание;
различие состояний передаётся не только цветом. Информация доступна и на телефоне
через меню приложения.

Глобус не является индикатором текущего здоровья сервиса. Первая версия не делает
фоновые HTTP-проверки, сетевое сканирование или проверки из внешней точки.

## Добавление, редактирование и порядок

- «Добавить приложение» открывает форму: название, URL, группа и иконка. Если
  название или URL позволяет предположить известное приложение, форма предлагает
  подходящее название и иконку. По одному произвольному IP и порту приложение
  достоверно не определяется. Сетевые запросы к введённой ссылке для распознавания
  не выполняются.
- Каталог иконок и правил распознавания небольшой и расширяемый. Начальное покрытие
  определяется найденными приложениями. Иконки поставляются локально с проверкой
  лицензий при реализации. Для остальных используется blueprint-иконка. Выбор
  пользователя имеет приоритет перед предположением системы.
- Можно изменить адреса, название, группу, иконку и внешний доступ, а также удалить
  ярлык. Удаление ярлыка не затрагивает сам сервис.
- Группы и приложения имеют сохраняемый порядок. В первой версии достаточно
  доступных кнопок перемещения в режиме редактирования; drag-and-drop необязателен.
- Пользовательские загрузки изображений и произвольные внешние источники иконок
  откладываются. Не требуется отдельный аккаунт или API-ключ для ярлыка.
- Одинаковые приложения на разных серверах поддерживаются как разные записи.
  Предупреждение о повторяющейся ссылке не должно запрещать намеренный дубль.

## Хранение и границы сервисов

Каталог хранится в центральной SQLite, в существующем постоянном SSD-backed volume.
Он не зависит от браузерного localStorage и доступен с разных устройств. Предлагаются
две новые таблицы: группы и приложения. Приложение содержит стабильный ID, название,
ссылки, состояние внешнего доступа, ключ иконки, группу, порядок и необязательный
стабильный ключ импорта. Конкретные имена колонок и маршрутов API оставлены разработчику.

Авторизованный API позволяет читать каталог, создавать и редактировать записи,
удалять ярлыки и менять порядок. Применяется существующая модель доступа дашборда,
проверка origin и ограничения размера тела. URL принимаются только с HTTP(S),
без встроенного имени пользователя и пароля. Токены не импортируются из виджетов,
Docker environment, SSH-конфигурации или иных секретов. URL с параметрами
авторизации требуют ручной замены обычным адресом приложения.

Фронтенд загружает каталог независимо от метрик хостов. В обычном режиме открытия
страницы сервер не опрашивает приложения и не пересобирает каталог. Новые таблицы
создаются добавочной миграцией; история и регистрации агентов сохраняются. Проверки
back-up/recreation должны подтвердить сохранность каталога, без изменения обещаний
об откате несовместимых миграций.

Дашборд не получает SSH-доступ, Docker socket или host devices. Разовый сбор выполняет
помощник вне продукта; учётные данные серверов не попадают в каталог. Изменения
Go-агента и аппаратных сборщиков для первой версии не нужны. Правила пассивного
мониторинга HDD сохраняются.

## Первоначальное заполнение

Частный собранный каталог используется как вход для первоначального заполнения.
Перед импортом разработчик сверяет записи с этим документом и сохраняет найденные
адреса, названия и иконки без секретов. Импорт выполняется в выбранный экземпляр
дашборда после готовности функции. Технический способ импорта оставлен разработчику;
в первую версию не обязателен отдельный пользовательский мастер импорта.

Предлагаемый основной список содержит 29 ярлыков. Четыре дополнительные записи —
сама существующая главная, сам дашборд и вспомогательные интерфейсы — сохранены
для выбора, но не предлагаются на новой главной по умолчанию. Эта подборка
является предложением помощника. Базы данных, очереди, workers, runners, MCP API
и служебные endpoints не становятся ярлыками только по наличию открытого порта.
Выключенные контейнеры во время сбора не запускались.

Повторный импорт того же каталога не создаёт дубли по стабильному ключу импорта,
не удаляет существующие записи и не перезаписывает ручные изменения. Можно
добавить только ещё отсутствующие записи. Обновление уже существующего адреса
выполняется явным редактированием.

Разработка и проверка первой версии выполняются локально. Обновление установленного
контейнера и импорт в него — отдельный этап после проверки готового результата;
настоящее проектирование не меняет установленную версию.

## Критерии готовности первой версии

- Пользователь открывает нужный сервис из сетки, находит его поиском и может
  добавить новый без редактирования YAML или исходного кода.
- Известные приложения получают подходящие локальные иконки, неизвестные — blueprint.
- Главная и существующий мониторинг имеют отдельные доступные маршруты.
- Каталог работает при недоступных агентах и сохраняется после обновления страницы,
  перезапуска и пересоздания контейнера с сохранённым volume.
- Глобус различает подтверждение владельца и найденный неподтверждённый адрес;
  отсутствие измерений не заменяется заявлением о доступности.
- CRUD, порядок, валидация URL, авторизация, импорт и сохранность данных проверяются
  поведением API и хранилища. Фронтенд проходит TypeScript и production build;
  основные сценарии проверяются в браузере на настольном и мобильном размерах.
- Реальные адреса, частный каталог, секреты и runtime-базы не включаются в Git.

## Что остаётся разработчику

Разбиение компонентов React, структура модулей Python, точные API-маршруты,
детали схемы SQLite и механизма первоначального импорта, подбор лицензируемых
иконок, адаптивные размеры сетки, оформление blueprint и конкретный набор
проверок. Эти решения не должны расширять первую версию до управления контейнерами,
постоянного обнаружения или нового конструктора виджетов.
