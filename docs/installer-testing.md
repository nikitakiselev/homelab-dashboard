# Проверка установщика

Обычные тесты проверяют сохранение токенов, YAML, переключение версий и откат при неудачной проверке API. Shell-скрипт проверяется `sh -n` и ShellCheck.

Для интеграционной проверки используется изолированный Debian-контейнер с checkout, смонтированным read-only в `/repo`:

```sh
docker run --rm --mount type=bind,src="$PWD",dst=/repo,readonly debian:12-slim sh /repo/tests/installer_smoke.sh
```

Тест действительно устанавливает пакеты, собирает React-интерфейс, запускает Python-сервисы от указанных в unit-файлах пользователей и проверяет авторизацию HTTP API. Затем повторяет установку, проверяет сохранение YAML/токена/истории и устанавливает отдельного агента.

В контейнере systemd не является PID 1: команды управления службами заменены тестовым shim, запускающим настоящую команду из unit-файла. Синтаксис unit-файлов отдельно проверяет `systemd-analyze verify`. Этот тест не доказывает поведение sandbox-настроек systemd и автозапуск после перезагрузки; их нужно проверять в полноценной VM/LXC. Shim блокирует запуск вне маркированного тестового контейнера и в установочный архив не входит.
