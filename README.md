# homelab-dashboard

Локальный дашборд для разнородных Linux-серверов и физических хостов Proxmox. React 19, TypeScript, Tailwind CSS 4, компоненты shadcn/ui (Radix, CVA), Recharts. Агент и центральный сервис — Python 3.10+ без сторонних Python-зависимостей.

## Структура исходников

```text
frontend/                     React-интерфейс
homelab/
  agent/
    linux.py                  Linux: /proc, SMART, NVIDIA/AMD/Intel GPU
    macos.py                  macOS: Mach, vm_stat, diskutil, ioreg
    runtime.py                Запуск, остановка и интервалы сборщиков
    api.py                    HTTP API отдельного агента
    __main__.py               python3 -m homelab.agent
  server/
    app.py                    Центральный API, опрос агентов, синхронизация
    bundle.py                 Формирование установочного архива агента
    __main__.py               python3 -m homelab.server
  shared/
    storage.py                Общая SQLite-история и сроки хранения
    packaging.py              Список исходников отдельного агента
deploy/                       Установщик и systemd-службы
tests/                        Проверки сборщиков, сервера и упаковки
```

`shared` не зависит от агента и сервера. Агент использует только `shared`; центральный сервис использует `shared` и фабрику сборщиков из `agent` для мониторинга собственной машины. Команды запуска сохранены после разделения пакетов.

## Архитектура

```text
Браузер → центральный сервис :8080 → агенты других хостов :9108
          встроенный Linux-сборщик      SQLite, история 90 дней
          SQLite, история 90 дней
```

Агент снимает метрики каждые 5 секунд. Центральный сервис опрашивает агенты раз в 10 секунд. Агент сам хранит историю с момента запуска: пятиминутные средние CPU, памяти, скорости сети и объёмы переданных данных. При подключении центральный сервис забирает прошлую историю, при перезапуске догружает пропуски. Синхронизация идёт страницами, максимум 4000 записей за опрос. Повторная загрузка текущего интервала не удваивает трафик. На графике 24 часов — интервалы 5 минут, 90 дней — 6 часов. История удаляется по истечении 90 дней. Если агент выключен, отсутствующие интервалы не восстанавливаются.

Центральный сервис на Linux автоматически собирает собственные метрики: для одного компьютера отдельный агент устанавливать не нужно. На macOS центральный сервис также автоматически собирает метрики текущего Mac (Mach CPU, vm_stat, netstat, diskutil и ioreg). Встроенный сборщик работает внутри процесса без дополнительного порта и пишет историю прямо в SQLite. Его можно отключить флагом `--no-self-monitor`. В LXC видны ресурсы контейнера; для физических дисков Proxmox нужен агент на самом хосте. Доступность SMART и GPU зависит от утилит и прав пользователя, от которого запущен центральный сервис.

### Что показывает

- CPU, число логических потоков, память (с учётом MemAvailable), uptime и ОС.
- GPU: NVIDIA через `nvidia-smi`, AMD через доступные sysfs-счётчики; несколько GPU видны в подробностях. Intel i915 — через `intel_gpu_top` из пакета intel-gpu-tools; загрузка — максимальная занятость GPU-движка. На встроенной Intel GPU отдельный объём VRAM не показывается. Отсутствие метрик GPU не означает отсутствие видеокарты.
- Накопители: физическая ёмкость, HDD/SSD/NVMe, модель, температура и SMART. Для SATA учитываются переназначенные, ожидающие и неисправимые секторы, для NVMe — critical warning и исчерпание ресурса записи.
- Занятое место и свободное место — по смонтированным файловым системам. Неразмеченное и несмонтированное пространство не считается свободным. Для ZFS/RAID/LVM файловая система может принадлежать нескольким дискам; во избежание удвоения она учитывается один раз. Точный пуловый учёт ZFS и состояние RAID пока не реализованы.
- Сеть: приём и передача в **байтах/с** (1024-based units), история и объёмы за выбранный период. По умолчанию суммируются физические интерфейсы. На VM/LXC без физических интерфейсов используется отфильтрованный набор виртуальных интерфейсов. При bond/bridge/VLAN укажите нужные интерфейсы явно, иначе возможен двойной учёт. Это суммарный трафик интерфейсов, включая транзитный; направления внутренних потоков не анализируются.
- SMART: «нет данных» показывается честно, без зелёного статуса. Проверка раз в минуту, может пробуждать спящие диски.

## Быстрый просмотр

```sh
npm ci
npm run build
python3 -m homelab.server --demo
```

Открыть http://127.0.0.1:8080. `--demo` добавляет четыре явно помеченных синтетических сервера и синтетическую историю. Крестик в баннере скрывает их; после добавления своего сервера демоданные также скрываются. Без `--demo` на Linux и macOS сразу отображается текущий компьютер; другие хосты добавляются по IP.

Для разработки запустите Python-сервис и `npm run dev` в разных терминалах. Vite проксирует `/api` на `127.0.0.1:8080`.

## Установка центрального сервиса в Ubuntu/Debian LXC

Python нужен версии 3.10 или новее. Node нужен только на машине сборки (Node 20.19+ / 22.12+). Контейнеру нужен сетевой доступ к агентам. Privileged LXC для центрального сервиса не требуется.

1. Выполните `npm ci && npm run build` в каталоге проекта.
2. Скопируйте `homelab/`, `dist/` и `deploy/` в `/opt/homelab-dashboard` контейнера.
3. Создайте пользователя, окружение и службу:

```sh
sudo useradd --system --home /var/lib/homelab --shell /usr/sbin/nologin homelab
sudo install -d -m 700 /etc/homelab
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
sudoedit /etc/homelab/dashboard.env
# Содержимое: HOMELAB_DASHBOARD_TOKEN=<сгенерированный токен>
sudo chmod 600 /etc/homelab/dashboard.env
sudo cp /opt/homelab-dashboard/deploy/homelab-dashboard.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now homelab-dashboard
```

Откройте `http://<IP-контейнера>:8080`, введите токен. В браузере он хранится только в sessionStorage текущей вкладки. Служба работает от отдельного пользователя, токены агентов хранятся в SQLite с правами 0600. Каталог StateDirectory — 0700. Вручную запускаемый сервер слушает только localhost; для других адресов обязательна переменная `HOMELAB_DASHBOARD_TOKEN` (24+ символа).

## Установка агента на каждом физическом Linux-хосте

Для Proxmox устанавливайте агент на сам хост, чтобы видеть его физические диски, CPU и GPU. Агент в LXC видит ограничения контейнера и доступное ему оборудование, а не полную картину хоста.

Скачайте архив из формы «Добавить сервер → Скачать Linux-агент». Он содержит только `homelab/agent/`, `homelab/shared/` и установочные файлы. React и центральный сервис в архив не входят.

```sh
tar -xzf homelab-agent.tar.gz
cd homelab-agent
sudo python3 deploy/install_agent.py
```

Установщик создаёт токен в `/etc/homelab/agent.env`, включает systemd-службу и при необходимости устанавливает утилиты чтения оборудования. Повторная установка сохраняет токен и историю. Подробности — в [deploy/AGENT.md](deploy/AGENT.md).

Разрешите TCP 9108 только от IP центрального сервиса в существующем firewall. В UI укажите IP, порт и токен. Установщик не меняет правила firewall и драйверы GPU. Служба агента работает от root для доступа к SMART; API управления хостом отсутствует.

Данные агента: `/var/lib/homelab-agent/agent.sqlite`. Данные центрального сервиса: `/var/lib/homelab/dashboard.sqlite`. Копируйте их при остановленной службе для резервирования. Если машина по тому же IP заменена, старый агент не принимается: удалите сервер из дашборда и добавьте заново.

## Доступ и ограничения

Первый вариант ориентирован на доверенную домашнюю LAN/VPN. Сейчас соединения HTTP: токены и метрики не шифруются транспортом. Не публикуйте порты в интернет; для недоверенной сети используйте VPN или TLS-терминацию. HTTPS к агентам, автоматическая установка по SSH, уведомления, управление питанием, Proxmox API и виртуальными машинами — следующие отдельные возможности, здесь они не реализованы.

История переживает перезапуск процессов, но не удаление SQLite. Данные за период отключения самого агента неизвестны. Во время первого замера CPU ещё нет базы для расчёта — показывается «—». SMART не является гарантией отсутствия будущих отказов.

## Проверки

```sh
npm run build
python3 -m unittest discover -s tests -v
```

Тесты проверяют подключение к HTTP-агенту, отказ при неправильном токене, восстановление сохранённой истории, отсутствие удвоения трафика, удаление, смену агента, TTL данных, авторизацию API и защиту запросов от другого Origin. Сборщик также проходит smoke-тест в изолированном Linux-контейнере (`tests/linux_smoke.py`). SMART и GPU требуют отдельной проверки на физическом оборудовании.

## Архив агента и автоматическая установка

Архив можно скачать из формы «Добавить сервер → Скачать Linux-агент». На Linux-хосте:

```sh
tar -xzf homelab-agent.tar.gz
cd homelab-agent
sudo python3 deploy/install_agent.py
```

Подробности, обновление с сохранением токена и выбор интерфейсов — в [deploy/AGENT.md](deploy/AGENT.md). Установщик работает на systemd, ставит недостающие smartmontools/util-linux через apt-get и не меняет firewall.

Последние метрики сохраняются центральным сервисом вместе с инвентарём оборудования. После перезапуска они отображаются как устаревшие до успешного опроса агента. Разрывы в истории сети не интерполируются как непрерывное наблюдение.

На macOS память считается как активные, wired и сжатые страницы. Сеть по умолчанию суммирует интерфейсы `en*`; можно задать HOMELAB_INTERFACES. Занятое место APFS считается по контейнерам один раз, без повторного учёта общих томов. GPU получает загрузку из IOAccelerator, SMART — из diskutil; недоступные показатели не подменяются нулями.
